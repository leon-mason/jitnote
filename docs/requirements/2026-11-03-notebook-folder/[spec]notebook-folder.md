# 笔记本文件夹和同步方式

- 状态：已确认
- 日期：2026-11-03
- 影响范围：Mac 客户端的笔记本文件夹；Mac 和 Android 的同步、冲突、历史版本行为
- 关联文档：[设计说明](../../design.md)、[AGENTS.md](../../../AGENTS.md)、[README](../../../README.md)

## 背景与问题

记特最大的优势是用仓库管理知识库，但现在用户看不到也选不了笔记本放在哪里。需要把笔记本文件夹设为 AI 的项目目录时，用户找不到它。

这也不只是路径问题。笔记本文件夹开放后，AI、终端等工具会和 App 同时读写同一份文件，而现有代码是按 App 独占这个目录写的。

当前行为：

- **存放位置：** Mac 放在 App 的 `Application Support/notebooks/<内部编号>`，Android 放在 App 私有目录。用户不能选择。
- **入口：** Mac 只在「管理笔记本」里有「在访达中显示」，没有复制路径。Android 没有打开文件夹和复制路径的入口。
- **自动提交：** 没有定时器。编辑内容 400–800 毫秒写一次磁盘；离开笔记、切到后台、退出、在 App 里重命名或删除时，把整个目录的改动提交。
- **冲突：** 同一处两边都改时，自动保留修改时间较新的一边，同步后再提供「看看另一个」「换成另一个」「就用现在的」。一边删除、一边修改时保留修改的一边。改的不是同一处时自动合并。
- **保存：** 写磁盘前不检查文件是否被别人改过。
- **感知外部变化：** 两端都没有文件监听。
- **同步开始时：** 无条件删除 `index.lock`；仓库处于未完成的合并等状态时，直接 `reset --hard`。
- **移除笔记本：** 删除整个文件夹。
- **提交者身份：** 同步时把云端账号写进这个仓库的 Git 配置，覆盖原有的 `user.name` 和 `user.email`。

## 目标

- 用户知道每个笔记本放在哪里，并能在创建时决定位置。
- 用户能从笔记本里方便地打开这个文件夹、复制它的路径，例如设为 AI 的项目目录。
- 不管谁在写这个文件夹，都统一用 Git 管理版本，不互相阻塞。
- 提交和推送合并成一个同步动作，冲突由用户决定。

## 用户与场景

- **创建或添加笔记本的用户：** 看到默认位置，可以接受，也可以改成自己指定的空目录。
- **用 AI 工作的用户：** 复制笔记本路径，设为 AI 的项目目录。AI 改文件并可能自行提交，用户回到记特点同步，这些改动被推到云端。
- **边用 App 边让 AI 工作的用户：** App 不阻止 AI 改任何文件，也不把 AI 改到一半的内容混进自动提交。
- **遇到冲突的用户：** 同步时看到有冲突的文档，看过两边内容后选择以云端还是本地为准。

## 需求范围

1. 笔记本文件夹：见下方「笔记本文件夹」规则。
2. App 与 AI、终端、其他 Git 工具平等地使用这个文件夹，不加锁。
3. App 不再在同步之外自动提交，同步时提交所有改动并推送。
4. 同步发生冲突时询问用户。

## 已确认规则与决策

### 笔记本文件夹（用户确认）

- 这一版只有 Mac 能选路径，Android 继续用 App 私有目录。
- 创建时默认路径是 `~/Jitnote/<仓库名>`，用户可以改。选到 iCloud、Dropbox 等同步目录时给警告。
- 只能指定空目录，新建笔记本和下载已有的都一样，保证创建时文件夹里的内容和云端一致。
- 创建后路径不可更改。文件夹找不到时显示提示，可以重新定位到云端地址相同的文件夹，或重新下载；重新下载不算修改路径。
- 顶部笔记本菜单里提供「打开文件夹」和「复制路径」。
- 已有的笔记本不自动迁移，只提供打开和复制路径。
- 删除笔记本时，默认路径下的文件夹一起删除；用户指定路径下的文件夹不删除。

### 共用和同步方式（用户确认）

- 不管谁在写，都统一用 Git 管理版本；AI 也可能提交，App 接手时可能只需推送。
- App 不加锁，不阻止 AI 修改。
- 提交和推送合并成一个同步动作，同步之外不自动提交。同步时提交所有改动。
- 例外：删除笔记、恢复历史版本之前，只把涉及的文件先记一版；新建笔记本的首次提交保留。
- 接受历史版本变粗：两次同步之间的改动没有版本。用户要能一眼看到还有未同步的修改。
- 有冲突时询问用户，代替自动保留较新版本和事后「换成另一个」：
  - 只有同一处两边都改才问；改的不是同一处继续自动合并。
  - 可以逐个文档选云端或本地，也可以全选。
  - 选之前能看两边内容。
  - 一边删除、一边修改也问，并写明哪边删除了。
  - 没选中的版本留在历史里。
  - 询问期间不动笔记本文件夹。
  - 取消时不合并、不推送，改动已在本机提交，下次同步再问。
- 编辑器跟随磁盘：文件就是唯一的事实。打开的笔记被外部改动时重新加载，不弹窗，最后写入的赢。接受的代价：两边同时改同一篇时，先写的内容可能被盖掉，没提交就找不回来；重新加载时光标可能跳动。

### 由“不加锁、纯 Git”推出的结论（Agent 判断，用户未提异议）

- **感知外部变化：** Mac 的文件树自动刷新。Android 的文件夹没有其他程序能写，不需要。
- **同步碰到别人的 Git 状态：** App 像其他 Git 工具一样，不清理别人的状态。`index.lock` 稍等重试；合并进行中就提示稍后再同步。只有 App 自己同步时留下的标记说明是自己崩溃，才恢复。这会改写设计说明「其他约定」里的崩溃恢复规则，两端一起改。
- **提交者身份：** 本地已配置身份时不覆盖，没配时才写入，符合产品原则第 4 条“不改动用户的东西”。两端一起改。
- **“所有改动”的范围：** `.gitignore` 之外的所有文件，和 `git add -A` 一致，不额外提示，也不自动改 `.gitignore`。没被忽略的 `.env` 也会被推上云。

### 由已确认规则带来的结果（Agent 判断，用户未提异议）

- 用户选的空文件夹就是笔记本文件夹，App 不再建子文件夹。文件选择窗口里可以新建文件夹。
- 用户指定路径的笔记本移除后，文件夹还在但不再是空目录，不能直接重新添加到原处。要选另一个空目录或自行清空。旧文件夹里没同步的改动不会自动带过去。
- 已有本地仓库的用户，也要重新下载到空目录。
- 已有的笔记本和默认路径下的笔记本一样，删除时一起删除文件夹。删除弹窗要写明这一点。
- 默认路径已被占用时，自动在文件夹名后加序号。`.DS_Store` 不算目录内容。

### 现有权威文档已规定，继续遵守

- 同步用 merge，不用 rebase，从不强推。
- 用户没改过的笔记，打开再保存逐字节不变。
- 遵守仓库已有的 `.gitignore`，App 不为迁就自己去改它；导入已有仓库时不写入任何文件。
- 界面不出现 Git、仓库、提交等词。
- 改一边的同步行为，另一边和对应测试一起改。

## 验收标准

路径（Mac）：

- 创建笔记本时能看到默认路径，并能改成另一个空目录；笔记本下载到显示的路径。
- 选择非空目录时被拒绝，并说明原因。
- 创建后，界面上没有修改路径的入口。
- 操作「打开文件夹」，访达打开笔记本主目录。
- 操作「复制路径」后，粘贴得到完整路径，可以直接用作 AI 的项目目录。
- 文件夹被移走后，App 显示提示，可以重新定位或重新下载，不会闪退，也不会静默重建。
- 删除默认路径下的笔记本，文件夹被删除；删除用户指定路径下的笔记本，文件夹和其中所有文件都还在；两种情况都不动云端。

共用：

- 外部工具提交后，工作区干净，点同步：该提交原样到达云端，App 不额外生成提交。
- 同样的情况，云端也有新提交：App 合并后推送，不强推，不改写外部工具的提交。
- 外部工具正在进行未完成的合并时点同步：合并状态和未提交的改动都不受影响，App 提示稍后再同步。
- App 打开笔记时，外部工具可以修改和提交任何文件，App 不阻止，也不因此报错。
- 外部工具新建或删除文件后，Mac 的文件树自动更新。
- 外部工具改了正在打开的笔记后，Mac 的编辑器不弹窗，显示磁盘上的新内容。没有编辑过的笔记不会因此被写回。

同步：

- 编辑笔记、离开笔记、切到后台、退出 App，都不产生新提交；内容已保存到磁盘。
- 点同步后，所有改动被提交并到达云端。
- 删除一篇未同步的笔记后，能从历史版本找回删除前的内容；恢复历史版本后，能找回恢复前的内容。
- 同一处两边都改过时，同步会询问用户，列出有冲突的文档，且询问期间笔记本文件夹里的文件不变。
- 选择云端或本地后，文档内容与所选一致，同步完成，没有强推；没选中的版本能在历史版本里找到。
- 取消询问后，云端没有变化，下次同步再次询问。

文案：

- 新增的界面文字不出现 Git、仓库、提交、分支等词。

## 不在范围内

- 笔记本创建后的路径修改或移动。
- 接管已有的本地仓库作为新笔记本。
- 任何形式的锁，或阻止其他工具写入。
- 自动修改用户的 `.gitignore`。
- Android 选择路径。
