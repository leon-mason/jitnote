# 向 Obsidian 靠齐的导航和打开方式

## 为什么要改

现在的导航学的是印象笔记：左边的目录只用来筛选，真正找笔记要看中间的列表。记特的笔记本就是一个 Git 仓库里的文件夹，用户（尤其是从 Obsidian 过来的）脑子里本来就是一棵文件树，多一层平铺列表反而绕。

这次改成 Obsidian 的方式：**文件树就是唯一的导航**。同时加上 Obsidian 的「默认打开方式」，让只想看不想改的时候不会误改笔记。

## 目标

1. 点文件夹是展开或收起，不再筛选。
2. 去掉平铺的笔记列表：Mac 从三栏变两栏，安卓首页变成全屏文件树。
3. 设置里可以选打开笔记时默认是编辑还是预览，每篇笔记打开后也能随时切换。

## 不做的事

- 搜索、最近打开、快速切换（去掉列表后找笔记会变难，所以搜索是紧接着的下一件事，但不在这次范围内）。
- 标签页、拖动移动文件、源码模式。
- 记住每篇笔记各自的模式；这个设置也不跨设备同步。
- 平板或大屏的安卓布局。

## 绝不能出现的情况

- 冲突入口消失：用户看不到冲突，就找不回另一个版本。
- 只是打开或预览一篇笔记就改动了文件。现有规则「没有真正编辑就不写文件」（`NoteSaver`）必须继续成立。
- 默认设成预览后，用户找不到怎么编辑。

## 文件树（两端相同）

### 点击

| 操作 | 结果 |
|---|---|
| 点文件夹（收起时） | 展开，并高亮它 |
| 点文件夹（展开时） | 收起，高亮移到它的上一级文件夹（顶层文件夹则取消高亮） |
| 点笔记或文本文件 | 打开，并高亮它 |
| 点图片 | 看大图 |
| 点其他文件 | Mac 右栏 Quick Look 预览；安卓照旧提示打不开 |
| 右键（Mac）或长按（安卓） | 原有菜单；文件夹另加「新建笔记」「新建文件夹」，建在这个文件夹里 |

所有文件夹都显示箭头，空文件夹也一样，这样点了能看到反应。整行都能点，箭头不再单独响应。

### 新建位置

新建笔记和新建文件夹都建在「当前位置」：

- 高亮的是文件夹：建在它里面。
- 高亮的是文件：建在这个文件所在的文件夹。
- 没有高亮，或高亮的东西已不存在（比如同步时被删）：建在笔记本根目录。

弹窗标题要写明位置，比如「在「会议」里新建笔记」。Mac 已经这样，安卓的新建笔记要补上。建好后自动展开上级文件夹并高亮新建的项。

### 记住状态

- **展开状态**按笔记本写进 `AppState`，重启后还在。重命名文件夹时一起更新路径（含子文件夹），删除时一起清掉；同步后已不存在的路径直接忽略。移除笔记本时清掉它的记录。
- **高亮**只存在内存里，不写盘。

### 排序

- 文件夹永远排在文件前面。
- 排序方式：名称 A→Z、名称 Z→A、修改时间（新→旧）、修改时间（旧→新）。全局记住。
- 按名称排时，文件夹和文件都按选定方向排；按修改时间排时，文件夹仍按名称 A→Z，同级文件按修改时间排，修改时间沿用「按分钟比较，同一分钟按名称」。
- 默认是**名称 A→Z**，和 Obsidian 以及现在的文件树一致。旧的 `noteSort` 是给列表用的，默认值是修改时间，继续用它的话所有人的文件树顺序都会突然变。所以换一个新字段 `fileSort`，旧字段直接丢弃（两端读取状态时都会忽略未知字段）。

文件夹右边的笔记数保留。

## Mac

`NavigationSplitView` 改成两栏，左栏从上到下：

1. 笔记本切换菜单
2. 同步状态
3. 冲突提示（只在有冲突时出现）
4. 「文件列表」标题和排序按钮
5. 文件树
6. 底部「新建文件夹」

去掉「全部笔记」「看全部」和中间栏。工具栏（新建笔记、同步）和菜单快捷键不变。右栏没有打开笔记时，提示「选一篇笔记」；笔记本是空的时，提示「点工具栏上的「新建笔记」写第一篇。」

实现时要注意：

- `OutlineGroup` 不能从外部控制展开，要换成自己按展开状态画的树。
- 不能靠 `List(selection:)` 的回调响应点击：再次点击已选中的行不会触发回调，文件夹就收不起来。
- 点文件夹只移动高亮，右栏继续显示正在看的笔记。
- 点左栏空白处取消高亮，这样可以回到根目录新建。

## 安卓

首页就是全屏文件树，去掉抽屉（☰ 和右滑手势）。`FileListDrawer` 改造成普通页面内容。

- 顶栏不变：笔记本切换、同步、⋮ 菜单。
- 树的上方依次是同步状态、冲突卡片（只在有冲突时出现）、排序和新建文件夹。
- 右下角「新建笔记」按钮不变。笔记本是空的时沿用现有的空状态提示。
- 点文件进入编辑页，返回键回到文件树；在首页按返回键退出 App，和现在一样。

实现时要注意：

- `key(nav.stack.size, screen)` 会在打开笔记时丢掉首页的所有 `remember` 状态。文件树成了主界面后，**返回时必须保持滚动位置，也不能闪一下空白**：滚动状态和已加载的树要放到 `Navigator` 里。
- 现在子文件夹是在同一个列表项里递归画的，文件多时会卡，也没法准确恢复滚动位置。要把可见的行展平后交给 `LazyColumn`。
- `nav.homeFolder` 改成高亮路径，`nav.expandedFolders` 移到 `AppState`。

## 编辑和预览

### 设置

Mac 在「设置 → 通用」，安卓在「⋮ → 设置」：

> **打开笔记时默认为**：编辑 / 预览

默认是**编辑**，升级后行为不变。存在 `AppState`（`defaultViewMode`）。

「预览」指只读显示。记特的编辑器本身就是所见即所得，所以只有这两种模式，没有 Obsidian 的源码模式。

### 切换

- Markdown 笔记打开后，工具栏（安卓顶栏）有一个切换按钮，Mac 另有快捷键 ⌘E。
- 切换只影响当前这次打开，不改设置。同步或看历史版本后回来保持当前模式；离开这篇笔记后恢复默认。
- **新建的笔记总是以编辑模式打开**，不管默认设置。
- `.txt` 等纯文本文件总是编辑，不显示切换按钮。

### 编辑器

现在 `readonly` 只能在 `load` 时传入。要给 `window.JitnoteEditor` 加 `setReadonly(readonly)`，同时切换 Crepe 的只读状态、格式工具栏和 `with-toolbar` 样式，不重新加载，滚动位置不变。

- 编辑器还没加载完就调用时，先记下来，加载完再生效。
- 切到预览不能取消 400ms 的保存定时器，否则刚打的字会丢。
- 宿主（`EditorController`、`NoteWebView`）的 `readonly` 现在是初始化时固定的，要改成可变，`onReady` 时读最新值。
- 改完要重新构建 `editor/`，并提交 `android/app/src/main/assets/editor/` 下的产物（Mac 也用这份）。更新 `main.js` 开头的接口说明和 `docs/design.md`。

预览模式下要确认：

- 不写文件。
- 安卓不弹键盘。
- 待办复选框点不动。
- 点图片能看大图，点链接在浏览器打开。

## 要清理的

没有地方再用的都删掉：`NoteIndex.notes` / `Note` / `preview`、`NoteList`、`NoteRow`、`ListHeader`、「全部笔记」和对应的 `total`。`friendlyTime` 其他页面还在用，保留。

文档要改：`README.md`、`README.en.md`（第 40、61 行）、`docs/design.md` 的「首页」一节，以及 Mac 设计文档里三栏的描述。

## 怎么验证

- 单元测试：两端的排序测试从 `notes` 移到 `tree`，补上当前位置推导、重命名和删除时更新展开路径的用例；旧状态文件（带 `noteSort`）能正常读取；编辑器补 `setReadonly` 的测试。
- CI 的三组命令都要通过：`./gradlew :app:testDebugUnitTest :app:assembleDebug`、`npm test`、`scripts/build-mac.sh --test`。
- 实际跑两端，走一遍：展开收起、重启后状态还在、新建到各个位置、重命名和删除展开中的文件夹、有冲突时能看到入口、默认预览时打开和切换、预览里退出后文件没被改动。Mac 的 `DebugHooks` 命令要跟着更新。
