# Windows 客户端

- 状态：已确认
- 日期：2026-11-04
- 影响范围：新增 Windows 桌面客户端；Mac 与 Windows 共用的笔记本文件夹规则
- 关联文档：[设计说明](../../design.md)、[笔记本文件夹需求](../2026-11-03-notebook-folder/[spec]notebook-folder.md)、[AGENTS.md](../../../AGENTS.md)、[README](../../../README.md)、[README.en.md](../../../README.en.md)

## 背景与问题

记特目前有 Android 客户端和 Mac 客户端。用户需要在 Windows 上使用当前 Mac 客户端已经提供的功能。开发、自动测试和打出可运行的 Windows 安装包都在 Mac 上完成。用户把这个包拿到 Windows 11 上安装并验收。正式发布与 Android、Mac 走同一次发版。

## 目标

- Windows 11 上有记特桌面客户端，用户能完成当前 Mac 客户端已有的笔记流程。
- 产品行为遵守设计说明里各客户端共用的规则。Mac 和 Windows 都能选择笔记本文件夹。
- 版本号与 Android、Mac 相同，Windows 包出现在同一次发布里。
- 在 Mac 上完成开发、自动测试，并打出可运行的 Windows 安装包。用户把该包拿到 Windows 11 上安装并验收。

## 用户与场景

- **使用 Windows 的用户：** 连接自己的云端账号，新建笔记本或添加已有笔记本，选定文件夹，用文件树打开笔记，编辑或预览，再同步到云端。
- **同时使用手机或 Mac 的用户：** 在 Windows 上改过的笔记本，其他设备同步后能拿到。两边改了同一处时，由用户选择以哪边为准。
- **从旧版本更新的用户：** 看到的版本号与手机、Mac 一致。下载 Windows 包后，自己退出正在运行的记特并换上新版本。
- **负责验收的用户：** 从 Mac 上拿到已经打好的可运行安装包，在 Windows 11 上安装，并验收界面、文件夹选择、凭据和安装结果。

## 需求范围

1. 提供 Windows 桌面客户端。除本文和设计说明「Windows 客户端」写明的差异外，功能对齐当前 Mac 客户端。共用行为以 [设计说明](../../design.md) 为准，本文不重复同步规则、编辑器和图片的正文。
2. 用户可见流程包括：连接云端账号，新建笔记本，用已有的仓库，选择笔记本文件夹，文件树导航，编辑和预览，同步，冲突时选择，历史版本，设置（显示隐藏文件、打开笔记时的默认方式），检查更新，图片只查看。
3. 界面是两栏：左边文件树，右边正在写的笔记。文案使用设计说明里的说法：笔记本、同步、历史版本、云端账号。
4. Windows 包进入现有发版流程，版本号与 Android、Mac 共用。

## 已确认规则与决策

### 用户确认

- 要做 Windows 客户端。对齐对象是当前 Mac 客户端已有的功能。
- Windows 也可以选择笔记本文件夹，使用与 Mac 相同的规则：创建时有默认位置并可改成空文件夹，创建后不能改位置，可以打开文件夹和复制路径，文件夹不见时可以重新检查、重新选择或重新下载，移除时按是不是默认位置决定删不删本地文件夹，云端都不动。平台差别只在设计说明「笔记本文件夹」里写明的路径、文件管理器和空文件夹判断。
- 只支持 Windows 11。不支持 Windows 10 及更早的系统。不为已经发布的旧版记特补做 Windows 包。
- 版本号与 Android、Mac 一起排，走同一个发版流程。
- 开发、自动测试和打包都在 Mac 上完成。用户把打好的可运行安装包拿到 Windows 上安装并验收。
- 两栏布局要做。Mac 上已有的操作能做成快捷键就做；某个快捷键做不到，就去掉那一个，按钮保留。
- 各客户端已经生效的共用规则继续有效。行为正文以设计说明为准。[Mac 客户端设计](../2026-10-31-mac-client/[spec]mac-client.md) 与设计说明或代码不一致时，以设计说明和代码为准。

### 技术选型（用户要求由规格确定）

- 语言和界面用 C# / .NET 与 Avalonia。在 Mac 上编译、跑同步测试，并打出可在 Windows 上运行的安装包。
- Git 用 LibGit2Sharp（libgit2）。同步规则从当前 Mac 客户端移植，测试与 Android、Mac 对应。
- 编辑器使用 Windows 11 自带的 WebView2，加载现有 `editor/` 的构建产物。
- 安装包是 Windows 11 x64 的自包含压缩包，里面的程序可以直接运行。与 Android、Mac 的包放在同一次发布里。Windows on ARM 这一版不做。
- 检查更新的查询方式与现有客户端相同：匿名，不带令牌，不发送笔记内容。下载完成后打开压缩包所在位置，由用户退出正在运行的记特再换上新版本。程序不覆盖正在运行的文件。
- 令牌存在当前 Windows 用户的凭据管理器里，只留在这台电脑上，不随用户配置漫游。不写入笔记本文件夹，不写入仓库，不放进明文的状态文件。账号和笔记本列表仍用本机的一个 JSON 文件，里面没有令牌。

### 快捷键（用户要求能做就做）

与 Mac 菜单一一对应：

| 操作 | Mac | Windows |
| --- | --- | --- |
| 新建笔记 | ⌘N | Ctrl+N |
| 新建文件夹 | ⇧⌘N | Ctrl+Shift+N |
| 同步 | ⌘R | Ctrl+R |
| 切换编辑/预览 | ⌘E | Ctrl+E |
| 设置 | ⌘, | Ctrl+, |

切换编辑/预览在光标位于编辑器内时也要生效。Mac 上编辑器会把这个键用于行内代码，仍然由应用切到另一种打开方式。其余快捷键如果被编辑器拦住、应用收不到，这一版去掉该快捷键，对应按钮保留。

## 验收标准

在 Windows 11 x64 上可以观察到：

- 能连接云端账号，能新建笔记本，能添加账号里已有的仓库。导入已有仓库时不往仓库里写文件。
- 创建笔记本时能看到默认位置（用户主目录下的 `Jitnote`），并能改成另一个空文件夹。只含 `desktop.ini` 或 `Thumbs.db` 的文件夹可以选。非空文件夹会被拒绝并说明原因。选了 OneDrive 等会自动同步的位置时有警告，仍能继续。创建后界面上没有修改位置的入口。
- 「打开文件夹」会在文件资源管理器中打开笔记本文件夹。「复制路径」得到的是完整路径。
- 文件夹被移走后，窗口换成说明页，可以重新检查、重新选择文件夹或重新下载到原位置。不会静默建一个新文件夹。
- 移除默认位置下的笔记本时，本地文件夹被删除。移除用户自己选的文件夹时，文件夹和里面的文件都还在。两种情况都不动云端。
- 窗口是两栏。文件树是唯一导航。能新建笔记和文件夹，能打开笔记编辑，能切换预览。预览不改文件。
- 没编辑过的笔记，打开再离开后，文件逐字节不变。
- 点同步后，本地改动到达云端。同步使用合并，不强推。
- 同一篇笔记两边都改了同一处时，同步列出这些文档并让用户选择。选择前笔记本文件夹里的文件不变。取消后云端不变，下次同步再问。没选中的那一版仍能在历史版本里找到。
- 其他程序改了笔记本里的文件后，文件树会更新。正在打开的笔记被改了，编辑器直接显示新内容。没编辑过的笔记不会因此被写回。
- 笔记里的图片能显示。保存笔记不改写图片引用。
- 关闭再打开后，云端账号仍然连着。笔记本文件夹和本机状态文件里都没有令牌。断开账号后，凭据管理器里不再留着可用的令牌。
- 检查更新不携带令牌，也不发送笔记内容。没有网络时，自动检查不打扰用户。有新版本时，下载完成后由用户自己替换正在运行的程序。
- 新建笔记、新建文件夹、同步、切换编辑/预览、设置这五项都有上表中的快捷键。光标在编辑器里时，切换编辑/预览的快捷键仍然有效。某一项如果被编辑器拦住而做不到，界面上仍有完成该操作的按钮。
- 界面不出现 Git、Markdown、仓库、提交、分支、push、merge。
- 发布出的版本号与同一版 Android、Mac 相同，同一次发布里有这个 Windows 压缩包。
- 同步规则的自动测试在 Mac 上通过，可运行的安装包也在 Mac 上打出。用户在 Windows 11 上安装该包，并完成上述界面检查。

## 不在范围内

- Windows 10 及更早的系统，以及 Windows on ARM。
- 给已经发布的旧版记特补做 Windows 包。
- Linux 桌面端、iOS 客户端。
- 设计说明「暂未做（后续）」里除 Windows 桌面端以外的条目：插入图片、查看历史版本时显示当时的图片、全文搜索、设备码登录、自动同步、中文以外的界面、把双链和 callout 渲染成可点元素。
- 改变 Android 或 Mac 已有行为。
- 上架应用商店。
- 自有服务器、账号体系、统计、广告。
- 为了某一个做不到的快捷键更换编辑器或界面方案。
