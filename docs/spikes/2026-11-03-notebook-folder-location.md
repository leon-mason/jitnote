# 笔记本文件夹：默认位置和选位置的实测

- 日期：2026-11-03
- 对应需求：[笔记本文件夹和同步方式](<../requirements/2026-11-03-notebook-folder/[spec]notebook-folder.md>)，任务单 06
- 环境：Mac 调试版（`scripts/build-mac.sh --debug`），用 `CFFIXED_USER_HOME` 指到临时目录，所以不碰真实的用户数据；云端是本机的 bare 仓库，没连任何真实账号

## 测了什么，结果如何

用调试版的遥控命令（`import <地址> [文件夹]`、`remove <名字>`，见 `mac/Sources/UI/DebugHooks.swift`）走真实代码路径：

| 步骤 | 结果 |
| --- | --- |
| 不指定文件夹下载一个仓库 | 落在 `<家目录>/Jitnote/<仓库名>`，`~/Jitnote` 不存在时自动创建；记录为默认位置 |
| 下载到一个用户选的空文件夹 | 笔记本就在那个文件夹里（里面直接是 `.git` 和文件，没有多一层子文件夹）；记录为用户选的 |
| 下载到一个已有文件的文件夹 | 被拒绝，提示“这个文件夹不是空的……”；原有文件没动 |
| 移除默认位置的笔记本 | 文件夹被删除 |
| 移除用户选的笔记本 | 文件夹和里面的文件原样保留 |

另外有单元测试覆盖：默认位置的命名和重名加序号、空/非空/有 `.DS_Store`/是文件/在另一个笔记本里面的判断、同步目录的警告、老笔记本的存档能读取、下载失败时用户选的空文件夹保留、下载会自动创建上层文件夹。

## 没测，不能当作结论

任务单 06 里“实测 `~/Jitnote` 的默认路径没有权限弹窗；iCloud 风险的实测结果记到这里”这一条**没有完成**：

- **权限弹窗**：上面的测试在 `/tmp` 下的临时家目录里跑，不会触发系统的文件夹权限询问，所以说明不了真实家目录里的情况。依据只是：系统只对桌面、文稿、下载、云盘、外接磁盘等位置弹权限询问，家目录下自己新建的 `~/Jitnote` 不在其中。这是一般认识，不是实测。
- **iCloud 云盘 / Dropbox 的影响**：没有实测。界面上的警告依据的是一般经验（两个程序同时改 `.git` 里的文件，同步到一半的状态会让版本记录损坏），没有量化，也没有复现。

怎么补上：

1. 在真实的家目录里用正式版或调试版添加一个笔记本，保存位置用默认的，观察有没有系统弹窗；
2. 另建一个笔记本放进 iCloud 云盘里的文件夹，在写笔记、同步的同时观察 `.git` 是否出现冲突副本（名字带 `2`、`3` 的文件）或 `git status` 报错。

在补上之前，对云盘位置只警告、不禁止。

## 文件夹找不到时（任务单 07）

同样用调试版（`relocate <名字> <文件夹>`、`redownload <名字>`）在临时家目录里走了一遍：

| 步骤 | 结果 |
| --- | --- |
| 打开着的笔记本，文件夹被从外面移走（里面有一篇没同步的新笔记） | 窗口自己换成“找不到文件夹”页，写明原来的路径；原路径上没有被重新建出空文件夹 |
| 「重新选择文件夹」指向一个不是笔记本的文件夹 | 被拒绝：“这个文件夹里没有笔记本。” |
| 指向移走后的那个文件夹 | 接回，窗口恢复成文件树，没同步的那篇还在 |
| 文件夹被整个删除 | 窗口再次换成说明页 |
| 「重新下载到原位置」 | 云端内容放回，`.git` 和笔记都在；没同步的那篇没有了（确认框里写明了） |

没做的：真的插拔外置硬盘。“上一级文件夹也找不到就不重新下载”有单元测试，但硬盘插回后的恢复只是用“把文件夹移回去、接回去”来代替。
