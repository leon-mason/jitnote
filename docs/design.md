# 设计说明

本文记录记特（Jitnote）的产品原则和关键技术决定，供各个客户端（Android、以后的 iOS / 桌面）共同遵守。

- 日期：2026-10-30
- 定位：**完全开源、没有服务器**。没有自己的账号体系和服务端数据，App 只和用户自己的 Git 托管平台打交道。

## 产品原则

1. **用户是不懂技术的普通人。** 界面不出现 Git、Markdown、仓库、提交、分支等词。对照：

   | 技术概念 | 界面说法 |
   | --- | --- |
   | 仓库 | 笔记本 |
   | 克隆 | 下载笔记本 |
   | 提交 | （同步时自动完成，不出现） |
   | fetch / pull / push | 同步 |
   | 合并冲突 | 两个地方都改过，请你选择以哪边为准 |
   | 提交历史 | 历史版本 |
   | 访问令牌 / 远端账号 | 云端账号 |

2. **真 Git。** 每个笔记本是完整的 Git 工作副本，有真实的提交，电脑上的任何 Git 工具都能接着用。不走平台 REST API 逐文件同步（那样本地没有 `.git`）。REST 只用于验证令牌、建私有仓库、列出账号里的仓库。
3. **没有服务器。** 令牌只存在设备上，App 只连接用户自己的 Git 托管平台。
4. **不改动用户的东西。** 遵守仓库已有的 `.gitignore`；App 自己的元数据只放在 `.jitnote/`（随仓库同步）和 `.git/jitnote/`（仅本机）。
5. **谁都可以写，都用 Git 管版本。【用户定】** App 不独占笔记本文件夹，也不加锁：不管是用户还是 AI 改的，都统一按 Git 管理。App、AI、终端和其他 Git 工具都可以直接改文件、提交。别人已经提交的内容，App 接手时只需合并、推送。

## 同步规则

一个「同步」按钮依次执行：

1. 把工作区所有改动提交成一个提交（`.gitignore` 之外的所有文件，包括别的程序写的，不额外提示；提交说明是人话：`编辑：笔记名`、`新建：…`、`删除：…`、`重命名：a → b`、`更新 N 个文件：…`，正文附设备名）。
2. `fetch` 默认分支。
3. **merge**（不 rebase，不改写历史）。能快进就快进。
4. 有冲突时问用户，不替用户决定：【用户定】
   - 先在内存里判断，不碰笔记本文件夹（合并到一半会把冲突标记写进文件，别的程序可能读到）。同一处两边都改了，或一边删除、一边修改，才算冲突；改的不是同一处的文件继续自动合并，不问。
   - 列出有冲突的文档，逐个选以这台设备还是云端为准，也可以一键全选；选之前能看两边的内容。一边删除的，写明是哪边删的。
   - 选完才合并：选中的版本写进文件，没选中的版本留在历史里（合并提交以两边都为父提交）。合并提交说明：`同步：合并云端修改（N 个文件两边都改了，按你的选择处理）`。
   - 取消时不合并、不推送。本地改动已在第 1 步提交，下次同步再问。
   - 问的期间云端又有新提交：选择按文档路径保留，新出现的冲突再问一次。
5. `push`。被拒（期间别人推送了）就回到第 2 步，最多 3 次。**从不强推。**

其他约定：

- 编辑器随输入把内容存到磁盘，离开笔记、App 切到后台时再存一次，但**不提交**：版本只在同步时记录，同步的第一步提交所有改动。重命名、退出 App、打开历史版本也不提交。【用户定】
- 有改动还没同步时，同步按钮上有圆点，笔记本的状态写“有未同步的修改”（别的程序已经提交但还没上传的内容也算）。回到 App、离开笔记、同步结束后重新检查。
- 不提交意味着两次同步之间的改动没有版本。会让没同步过的内容消失的操作，先只把涉及的文件记一版：删除笔记或文件夹、恢复历史版本。恢复出来的内容随下一次同步记录。【用户定】
- 同步进行时编辑器只显示“正在同步”，结束后重新加载文件，避免同步过程中写文件。
- 同步开始时在 `.git/jitnote/` 留一个标记，正常结束后删除（同步失败但留下了未完成的合并时保留）。上次同步中途崩溃（标记还在，仓库停在 MERGING 状态或残留 `index.lock`）时，下次同步先放弃未完成的合并再重来；本地改动在合并前已经提交，所以不会丢。
- 没有标记时，未完成的合并和 `index.lock` 都是别的程序的（AI、终端、其他 Git 工具），同步不清理：`index.lock` 最多等 3 秒（别的程序一条命令持有它远不到 1 秒），还在就提示“有其他程序正在处理这个笔记本，请稍后再同步”；合并没有完成就提示等它完成后再同步。
- 同步会在仓库里写入提交者名字和邮箱（`user.name`、`user.email`），好让别的工具在这里提交时有名字可用；仓库里已经配置过的不覆盖。App 自己的提交总是明确指定作者。
- 新建笔记本：在平台上建**私有**仓库（`auto_init`），仓库名由笔记本名转成英文，纯中文名用 `notes-xxxxxx`；仓库描述写 `[Jitnote] 显示名`，用于在第二台设备上识别；`.jitnote/notebook.json` 记录显示名等信息。
- 删除笔记本只删除本机副本，不删除云端仓库；本机文件夹是否一起删除，见「笔记本文件夹」。

## 首页

参考 Obsidian：一次只看一个笔记本，**文件树就是唯一的导航**，没有平铺的笔记列表。

- 打开 App 直接进入上次用的笔记本（`currentNotebookId`）。顶部标题是笔记本名，点开可以切换，最下面是「管理笔记本…」（添加、重命名、移除、同步，即原来的首页）。
- Android 的首页、Mac 的左栏就是文件树：像 Obsidian 一样列出所有文件和文件夹，显示完整文件名（含后缀），文件夹在前、带笔记数（含子文件夹）。所有文件夹都显示箭头，空文件夹也一样；整行都能点。点文件夹是展开或收起（展开时再点收起，高亮回到上一级文件夹），点笔记或文本文件打开并高亮，点图片看大图；Mac 右键、安卓长按可以看历史版本、重命名、删除，文件夹另有「新建笔记」「新建文件夹」；底部或树的上方有「新建文件夹」。
- 新建笔记和新建文件夹都建在「当前位置」：高亮的是文件夹就建在里面，是文件就建在它所在的文件夹，没有高亮或高亮的东西已不存在就建在笔记本根目录。弹窗标题写明位置。建好后自动展开上级并高亮新项。点树的空白处取消高亮。
- 展开状态按笔记本记在 `AppState`，重启后还在；重命名文件夹时一起更新路径，删除时一起清掉，同步后已不存在的路径忽略。高亮只在内存里，不写盘。
- 排序：名称 A→Z / Z→A、修改时间（新→旧 / 旧→新），全局记住（字段 `fileSort`，默认名称 A→Z）。文件夹永远在文件前面；按修改时间排时文件夹仍按名称，同级文件按修改时间，按分钟比较，同一分钟按名称。
- 默认打开方式：设置里的「打开笔记时默认为 编辑 / 预览」（`defaultViewMode`，默认编辑，不跨设备同步）。预览是只读显示，不写文件、不弹键盘、待办复选框点不动，点图片仍能看大图、点链接在浏览器打开。Markdown 笔记打开后可随时切换（Mac ⌘E 或按钮，安卓顶栏按钮），只影响当前这次打开，同步或看历史版本回来保持当前模式。**新建的笔记总是编辑模式**；`.txt` 等纯文本总是编辑，不显示切换按钮。
- 文件树和打开的笔记跟着磁盘走：别的程序（AI、终端、访达）新建、删除、重命名、修改文件，Mac 的文件树自动更新；打开的笔记被改了，编辑器直接显示新内容，不弹窗，**最后写入的赢**。代价是两边同时改同一篇时，先写的内容可能被盖掉，没提交就找不回来。【用户定】
  - 靠内容区分自己和别人的写入：App 自己保存后文件正好等于它写的内容，不会重新加载。没编辑过的笔记，重新加载也不会写回，逐字节不变。笔记被删除或移走后，不会因为编辑器里还有内容就把它写回来。
  - 以 `.` 开头的名字（`.DS_Store`、`.obsidian`、别的编辑器的临时文件）不引起刷新，除非开着「显示隐藏文件」；`.git` 里面的变化不监听，回到 App 时再检查有没有未同步的内容。
  - Android 的笔记本在 App 私有目录，别的程序碰不到，不需要。
- 以 . 开头的隐藏文件默认不显示，「设置」里可以打开「显示隐藏文件」；Git 自己的 `.git` 始终不显示（手动改它会弄坏笔记本）。

## 笔记本文件夹

每个笔记本是电脑上的一个文件夹，里面就是 Git 工作副本。Mac 上用户可以决定它放在哪里，以便把它交给 AI 工具当项目目录。【用户定】

- **只有 Mac 能选**：Android 的笔记本继续放在 App 私有目录，那里别的程序碰不到，用户也找不到，没有这个需求。
- **创建时给出默认位置**：`~/Jitnote/<仓库名>`，重名时在后面加序号（`<仓库名> 2`），已经有内容的文件夹绝不动。新建和下载已有的仓库都一样。用户可以点「更改…」换成自己的文件夹，选择窗口里能新建文件夹。位置显示在创建界面里，并写明创建后不能更改。
- **只能选空文件夹**：这样笔记本一开始的内容和云端完全一致。非空（`.DS_Store` 不算）、是文件、或者在另一个笔记本里面的，都拒绝，并说明原因。选的文件夹就是笔记本文件夹本身，App 不会在里面再建子文件夹。
- **iCloud 云盘、Dropbox 等会自动同步的位置**给出警告，但不禁止：它们和笔记本自己的同步会抢着改 `.git`，同步到一半的状态可能弄坏版本记录。
- **创建后位置不能更改**，界面里没有这个入口。
- **随时能找到**：左栏顶部的笔记本菜单里有「打开文件夹」（在访达里打开）和「复制路径」；「管理笔记本」里也有「复制路径」。老笔记本（放在 App 的 `Application Support` 里）不迁移，同样可以打开和复制路径。
- **移除笔记本时的文件夹**：放在默认位置（`~/Jitnote` 下，以及老笔记本所在的 App 目录）的，文件夹一起删除；用户自己选的，不删，里面所有文件原样留着（包括没同步的修改）。两种情况的确认框都写明文件夹的路径和会发生什么，都不动云端。选了位置的笔记本移除后，那个文件夹就不再是空的，想再添加要选一个新的空文件夹。
- **文件夹找不到时**（被移走或删除，或所在的硬盘没插上）：笔记本留在列表里，主窗口换成一页说明，写明它原来放在哪，并给三条路：【用户定】
  - 「重新检查」：硬盘重新插上后点；回到 App 时也会自动检查，文件夹被移走或删除时窗口立刻换成这一页。
  - 「重新选择文件夹…」：指向它被移到的地方。那个文件夹必须正是这个笔记本（云端地址相同）、没被别的笔记本占用，否则拒绝并说明原因。没同步的修改都在文件夹里，原样保留。这是找回，不是修改位置。
  - 「重新下载到原位置…」：把云端内容放回原来的位置。原位置必须不存在或为空；而且它上一级文件夹也找不到时（硬盘没插）拒绝，不会在挂载点那里凭空建出空文件夹；只有 `~/Jitnote` 和 App 自己的目录在上一级不存在时会补建。没同步的修改，如果原文件夹找不回来，就没有了，确认框里写明。
  - 文件夹不可用时同步会提示“找不到这个笔记本的文件夹”，不去建新的；新建笔记和文件夹前也先检查一遍。除这两条路外，没有任何改位置的入口。
- 下载失败时，用户选的空文件夹保留（只清掉下载放进去的东西），App 自己建的文件夹则一起清掉。

## 用已有的仓库做笔记本

很多人已经有一个放笔记的仓库（Obsidian、Typora、在电脑上手写的），不想新建。

- 「添加笔记本 → 用已有的」列出账号能访问的**所有**仓库（自己的、协作的、组织的，GitHub / Gitee 各最多 500 个），本 App 建的笔记本排在前面，其余按最近更新排序；超过 6 个时出现搜索框。每项写明“仅自己可见 / 所有人可见”、多久前更新、属于哪个组织。已经在手机上的标为“已在手机上”，不能重复添加。
- 点选后问两件事：在 App 里叫什么（默认用仓库名），以及放在哪个文件夹（Mac，默认位置见「笔记本文件夹」）。并用大白话说明“原有文件原样保留，手机上写的会同步回去”；公开仓库、超过 50 MB 的仓库会额外提醒。
- 也可以粘贴网址：浏览器地址栏里的网址（哪怕是 `…/tree/master/某个文件夹`）会自动换成正确的下载地址。
- 导入**不写入任何东西**：不加 `.jitnote/`，不改仓库描述，不改分支（沿用仓库的默认分支，`master` 也可以）。以 `.` 开头的文件夹（如 `.obsidian`）在 App 里隐藏但照常同步。
- 文件列表按修改时间排；同一次下载的文件时间相同，按名字排。

## 编辑器

`editor/` 是一个独立网页，用 [Milkdown](https://milkdown.dev/) 的 Crepe 组件做所见即所得编辑，各客户端用 WebView 加载打包好的离线文件。

- 只启用笔记需要的功能：列表/待办、链接、图片、表格、选中文字后的浮动工具栏；不启用数学公式、代码高亮编辑器、AI、斜杠菜单（会和普通文字里的 `/` 冲突）。
- 自带底部中文工具栏：标题、加粗、列表、编号、待办、引用、撤销、重做。
- **不改动用户没碰过的内容**（导入已有仓库时尤其重要）。编辑器保存时会重新生成整篇 Markdown，所以要保证“打开再保存”逐字节不变：
  - YAML 文件头原样保留；列表符号写 `-`，分隔线写 `---`；表格按显示宽度对齐（中文算两格）。
  - CommonMark 不认识的 Obsidian 写法会被转义，保存前还原：`[[双链]]`、`![[嵌入]]`、`> [!callout]`、行首 `#标签`、行首 `==高亮==`，以及不可能变成链接的普通方括号（如 `a[0]`）。
  - 不用 Crepe 的图片块功能（它把图片说明改写成尺寸比例），图片保持普通 Markdown 图片。
  - 只有用户真正编辑后才回写文件。
  - `editor/test/roundtrip.test.js` 锁定以上行为（`npm test`）。已知仍会变化的：引用式链接会变成行内链接；未对齐的表格第一次保存会被对齐。
- 宿主接口（各平台一致）：
  - 宿主 → 编辑器：`window.JitnoteEditor.load(markdown, { readonly, baseUrl })`、`window.JitnoteEditor.getMarkdown()`、`window.JitnoteEditor.setReadonly(readonly)`（不重新加载，直接在编辑和只读间切换）
  - 编辑器 → 宿主：`window.JitnoteHost.onReady()`、`window.JitnoteHost.onChange(markdown)`（防抖，仅在真实编辑后）
- 只有用户真正改过才回写文件；只是打开、看完、返回，不会产生任何修改或提交。

## 图片

笔记来自不同的编辑器，引用图片的方式各不相同，App 都要能显示，而且**只显示、不改写**引用：

| 写法 | 来源 | 查找方式 |
| --- | --- | --- |
| `![猫](assets/cat.png)` | Typora、VS Code | 相对笔记所在文件夹 |
| `![猫](附件/cat.png)`、`/附件/cat.png` | Obsidian | 相对笔记本根目录 |
| `![[cat.png]]`、`![[cat.png\|300]]` | Obsidian | 按文件名在整个笔记本里找，路径最短的优先；`\|300` 设显示宽度 |

- 查找由宿主完成（`JitnoteHost.resolveFile`，Android 见 `NoteAssets.kt`），永远不会解析到笔记本外面或 `.git` 里。找到的图片经 `https://appassets.androidplatform.net/notebook/` 从笔记本目录读取。
- `![[图片]]` 在编辑器里是一个独立的图片节点，保存时原样写回 `![[…]]`；`![[另一篇笔记]]` 这类非图片嵌入保持文字。
- 点笔记里的图片、或文件列表里的图片文件，打开全屏查看：双指缩放、双击放大/还原、拖动。超大图片按最长边 4096 像素解码，避免内存不足。文件列表里图片显示缩略图。

## 检查更新

App 不在应用商店上架，新版本发布在本项目的 [GitHub Releases](https://github.com/leon-mason/jitnote/releases)，App 自己检查和下载。

- 打开 App 时检查，每天最多一次（成功查过才算），没网或连不上 GitHub 时什么都不提示。首页「⋮ → 检查更新」可以手动查，这时会明确告诉用户结果。
- 只看最新的正式版本（不看草稿和预发布），版本号按数字逐段比较。
- 发现新版本先弹窗问：版本号、更新内容（发布说明）、安装包大小，「以后再说」/「更新」。点「更新」才下载，弹窗显示进度、可以取消；下载完马上打开系统安装界面。第一次更新需要用户允许「安装未知应用」，弹窗用一句话说明原因，带去设置页，返回后自动继续。
- 查询是匿名的，不带令牌，不发送任何笔记内容。
- 正式包在 GitHub Actions 里用固定的正式密钥签名（`.github/workflows/release.yml`）。Android 只允许同一密钥签名的新版本覆盖旧版本，所以这把密钥不能换、不能丢。

## App 图标

两端的图标都由 `scripts/make-icons.py` 从 `docs/logo.png` 生成。logo 里的图案几乎贴着自己的边，所以不能原样当图标。【用户定】Mac 图标的图案和留白比例跟 Android 图标一致：图案缩小，圆角底板的外形不变。

## Android 技术选型

| 项目 | 选择 | 原因 |
| --- | --- | --- |
| 语言 / UI | Kotlin + Jetpack Compose（Material 3） | 原生体验、稳定 |
| Git | JGit 5.13 | 成熟的纯 Java 实现，无需原生库；5.13 是最后一个面向 Java 8 的版本，在 Android 上兼容性最好 |
| 令牌存储 | Android Keystore（AES-GCM） | 密钥不出设备；关闭系统备份 |
| 本地状态 | 一个 JSON 文件（账号、笔记本列表） | 数据量很小，不需要数据库 |
| 编辑器 | WebView + `editor/` | 与其他平台共用 |

JGit 被隔离在 App 自己的配置里（不读系统 git、不读 `~/.gitconfig`），见 `GitEnvironment.kt`。
